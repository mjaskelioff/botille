## Gotchas

- **macOS is client-only** — On Darwin the image is the same Linux derivation (`aarch64-darwin` hosts get the `aarch64-linux` image), substituted from cachix or built inside the podman machine via `scripts/mac-build-image.sh`; a Mac cannot build it natively. The launcher uses the host's `podman` (not the Nix one) against a running `podman machine`, and skips the firewall OCI hooks, so there is no LAN blocking on macOS. When editing `flake.nix`/`nix/launcher.nix`, keep the Linux image derivation unchanged (check `nix eval --raw .#packages.aarch64-linux.container.outPath` before and after) or cache hits are lost.
- **SELinux hosts need `label=disable`** — per-run MCS categories make one run's writes to the shared volumes unreadable by the next run (first seen in the podman machine's Fedora CoreOS VM; applies to Fedora/RHEL hosts too). The base config sets `securityOpt = [ "label=disable" ]` in `nix/container-options.nix`; do not remove it.

- **podman load fails on re-load** — `podman load` of an image that already exists errors with `copy_file_range: is a directory`. The launcher handles this automatically (skips load when the same Nix store path is already loaded, `podman rmi` before reload otherwise). If debugging manually, always `podman rmi` first.
- **`CACHIX_AUTH_TOKEN` secret** — CI pushes to the `delirium-systems` cachix cache. The secret must be configured in GitHub repo settings (Settings > Secrets > Actions) for pushes to work. Without it, CI still runs but skips pushing.
- **Launcher args go to the container command**, not to `podman run` flags. `nix run .# -- foo` runs `foo` inside the container (overriding default CMD `/bin/bash`). Exceptions: `--allow-lan`, `--devshell`, `--host-port`, `--port`/`-p`, `--share-claude`, `--share-memory`, `--volume`/`-v` are consumed by the launcher before the container command.  Parsing stops at the command or an explicit `--`; subsequent flags belong to the command.  Runtime flags layer on top of declarative config from `extraContainerModules`.
- **Container config is declarative** — Podman run flags (volumes, ports, env, capabilities, dns, etc.) are defined as NixOS-style options in `nix/container-options.nix` and rendered by `nix/render-podman-flags.nix`. Downstream flakes customise via `extraContainerModules` in `lib.mkApp`. List/attr options (volumes, dns, capabilities, securityOpt) **merge** with base values — setting `volumes` in `extraContainerModules` appends to the base mounts, it does not replace them. Use `lib.mkForce` to override base values entirely. Scalar options (network, userns, logDriver) override the base via plain assignment. Runtime CLI flags (`-v`, `-p`) append after declarative ones, so they can override (last `-v` for a given mount point wins).
- **Run from project directories only** — The physical host `$PWD` is bind-mounted read-write at a stable `/work/<name>-<hash>` path.  Renaming or moving the host directory changes this identity.  `BOTILLE_WORKDIR` holds the container path.  Running from `$HOME` or `/` exposes your entire home directory or root filesystem to the AI agent.  Always `cd` into a project directory first.
- **Nix store updates are non-destructive** — On image update, new store paths are merged alongside old ones (not wiped). Old paths stay on disk so running containers keep working. The nix DB is reset and reloaded from the new image closure. Run `nix-store --gc` inside the container to reclaim orphaned old paths when no other containers need them.
- **Codex sandbox needs startup capabilities released** — Bubblewrap rejects inherited capabilities in a non-setuid process.  Keep the entrypoint’s `setpriv` step, which clears inherited and ambient `SYS_ADMIN` after the Nix store bind mount and before running the command or devshell.  Any further capability added via `extraContainerModules` stays in the ambient set and breaks bubblewrap again; that trade-off is documented on the `capabilities` option.
- **Shell recovery** — If the shell environment breaks after an update, `source /var/nix-store/botille-reload` reconstructs PATH from the current store and re-sources `.bashrc`.
